# mmEgoHand

Official implementation of **mmEgoHand: Egocentric Hand Pose Estimation and
Gesture Recognition with Head-mounted Millimeter-wave Radar and IMU**.

Modern VR systems commonly use downward-facing cameras for hand interaction,
but those cameras may also capture recognizable visual information about the
user and the surrounding environment. mmEgoHand investigates a
privacy-conscious alternative based on a head-mounted TI IWR6843 mmWave radar
and a six-channel inertial measurement unit (IMU).

The system uses a two-stage, pose-mediated recognition pipeline:

1. **mmHandPose** fuses radar heatmaps and IMU measurements with an end-to-end
   Transformer to estimate 21 three-dimensional joints for one or two hands.
2. A downstream **ResNet-50** classifies eight interaction gestures from the
   estimated pose sequence.

The paper evaluates 10 volunteers in controlled sitting, lying, and standing
conditions. Under the fixed repetition-based protocol supplied in this
repository, the two-stage system achieves 90.80% gesture recognition accuracy.
The paper also reports cross-user, cross-hand, cross-posture, cross-scene, and
few-shot calibration experiments. These results characterize controlled,
quasi-stationary interaction; walking and turning are outside the scope of the
current dataset.

This repository consolidates the paper implementation with the earlier
[WhisperYi/mmVR](https://github.com/WhisperYi/mmVR) release. It removes
machine-specific paths, makes device selection explicit, retains compatibility
with the original pose checkpoints, and provides fixed split files and separate
training/evaluation entry points.

## Paper Configuration

The canonical configuration is [`configs/paper.yaml`](configs/paper.yaml).

| Item | Setting |
| --- | --- |
| Input | 2 s, 40 synchronized samples uniformly resampled to 30 frames |
| Radar tensor | `30 x 256 x 128` |
| IMU tensor | `30 x 6` |
| 3D-CNN channels | `8, 16, 32, 64, 64` |
| IMU encoder | 2-layer LSTM, hidden size 512 |
| Transformer encoders | 6 radar + 6 IMU blocks |
| Pose / context decoder | 6 / 30 blocks |
| Hidden size / heads | 512 / 8 |
| Active FFN size | 1024 (`2D`) |
| Candidate queries / joints | 100 / 21 |
| Fusion weights | radar 0.9, IMU 0.1 |
| Pose optimizer | AdamW, LR `1e-4`, weight decay `1e-4` |
| Pose schedule | 200 epochs, batch 32, LR x 0.5 every 100 epochs |
| Gesture classifier | ResNet-50, 500 epochs, batch 32, LR `1e-2` |

The checkpoint-compatible pose model has exactly **293,110,429 parameters**
(1118.13 MiB in FP32). The original source registered 2048-dimensional
Transformer projections and three input projections that are not called by the
forward path. They remain enabled in `paper.yaml` because they are present in
the paper checkpoint and are included in its parameter/memory profile. The
executed FFN path is `512 -> 1024 -> 512`. See
[`docs/PAPER_CODE_ALIGNMENT.md`](docs/PAPER_CODE_ALIGNMENT.md).

## Installation

### Prerequisites

- Linux is recommended for training and dataset preprocessing.
- Python 3.9 or newer.
- A CPU, or an NVIDIA GPU with a PyTorch-compatible CUDA installation.

Clone the consolidated repository:

```bash
git clone https://github.com/airslab2020/mmEgoHand.git
cd mmEgoHand
```

Create a virtual environment and install the package:

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e .
```

Conda users can instead create the provided environment:

```bash
conda env create -f environment.yaml
conda activate mmegohand
pip install -e .
```

Install the PyTorch build appropriate for the host CUDA version when GPU
acceleration is required.

## Data

### Download

The dataset originally released with
[WhisperYi/mmVR](https://github.com/WhisperYi/mmVR) is available from
[Kaggle](https://www.kaggle.com/datasets/cdf079d9f49052500a08482b692eac6758d83e6b1ba9868d677c5cb814c427aa).
Download `dataset.zip`, extract it, and place the data under `data/`. The
original archive uses some legacy directory names; the current loaders accept
those aliases as described below.

### Layout

Place the downloaded dataset under `data/`:

```text
data/
  mmwave/          # <sample>.mat, HDF5 dataset key: data
  imu/             # <sample>.npy
  pseudo_labels/   # <sample>.npy, MediaPipe-derived pseudo labels
  pose_outputs/    # generated by scripts/export_poses.py
```

Legacy directory names `kpt_gt`, `keypoint_gt`, `kpt`, `kpt_output`, and
`keypoint_output` are accepted by the loaders. They are read-only compatibility
aliases; new datasets should use `pseudo_labels` and `pose_outputs`.

Each split row has the form:

```text
sample_name,subject-hand setting,scene,gesture,repetition
```

The fixed protocol places repetitions 5, 10, 15, and 20 in the test set and the
remaining repetitions in the training set. After quality filtering, the
provided manifests contain 4,151 training and 1,055 test samples.

This periodic holdout distributes test repetitions across the acquisition
sequence while keeping each complete trial in only one partition. Because
training and test repetitions still come from the same subject and condition,
the protocol is not equivalent to a contiguous chronological or cross-session
holdout; this temporal-correlation risk is discussed as a paper limitation.

Validate the manifests with:

```bash
python scripts/validate_splits.py
```

To prepare precomputed range-angle/range-Doppler heatmaps and IMU CSV files:

```bash
python scripts/prepare_sensor_data.py \
  --range-angle-dir /path/to/RangeAngle \
  --range-doppler-dir /path/to/RangeDoppler \
  --imu-csv-dir /path/to/imu_csv \
  --output-root data
```

To generate MediaPipe world-landmark pseudo labels:

```bash
pip install -e ".[labels]"
python scripts/generate_pseudo_labels.py \
  --video-dir /path/to/videos \
  --output-root data
```

The label generator discards a clip when more than 40% of its frames lack the
expected one- or two-hand detections, interpolates retained gaps, and resamples
the sequence to 30 frames. Verify the camera convention on a few clips; use
`--swap-handedness` when MediaPipe's left/right labels are reversed.

## Stage 1: Pose Estimation

```bash
python scripts/train_pose.py --data-root /path/to/data
python scripts/evaluate_pose.py outputs/pose/best.pt --data-root /path/to/data
```

The paper configuration preserves the original loaders' `drop_last=True`
behavior. Add `--include-partial-eval-batch` during training or
`--include-partial-batch` during evaluation to cover every item in the split.
For downstream classification, the legacy script divided correct predictions
from complete batches by the full split size. The release reports that value as
`accuracy` and also reports `processed_accuracy`; setting
`legacy_split_denominator: false` selects the conventional processed-sample
denominator.

MPJPE is reported in millimeters against the MediaPipe-derived 3D pseudo
labels. This model metric is not normalized by palm width, hand length, or any
other hand-size statistic, and it should not be interpreted as error against
motion-capture ground truth. The paper's hand-height-normalized error is a
separate pseudo-label validation that compares MediaPipe outputs with manual 2D
annotations; it is not a normalized model MPJPE.

## Stage 2: Gesture Recognition

Export Hungarian-matched pose predictions, then train the downstream model:

```bash
python scripts/export_poses.py outputs/pose/best.pt --data-root /path/to/data
python scripts/train_gesture.py --data-root /path/to/data
python scripts/evaluate_gesture.py outputs/gesture/best.pt \
  --data-root /path/to/data
```

For a single-hand sequence, the absent left/right slot is zero-padded according
to the executing-hand metadata, producing a fixed `30 x 42 x 3` input. Two-hand
sequences already contain both 21-joint slots.

```bash
python scripts/profile_model.py --device cuda --profile-flops
```

The profiler reports parameter memory, clip latency, real-time speedup, data
frame rate, process memory, and CUDA memory where available.
